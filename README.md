# Рейсы и счета

Небольшая система учёта рейсов сборных грузов и счетов клиентам.

## Запуск

Нужен PHP 8.2+ с расширением `pdo_sqlite`.

```bash
php bin/reset-db.php
php -S localhost:8000 -t public
```

Открыть http://localhost:8000.

То же через Docker (Windows / macOS / Linux):

```bash
docker run --rm -it -p 8000:8000 -v "$PWD":/app -w /app php:8.4-cli \
    sh -c "php bin/reset-db.php && php -S 0.0.0.0:8000 -t public"
```

### Docker Compose (с префиксами `test1_`)

Чтобы контейнеры и образы имели префиксы `test1_`, используем `docker-compose.yml` и локальный `Dockerfile`.

Запуск:

```bash
docker compose build
docker compose up
```

После старта открыть http://localhost:8000.

Docker Compose создаёт базу только при первом запуске и сохраняет изменения при перезапуске контейнера.

`php bin/reset-db.php` пересоздаёт базу `data/app.sqlite` из `data/schema.sql` и `data/seed.sql`. Так можно вернуть
исходные данные в любой момент.

## Что внутри

| Папка | Что в ней |
|---|---|
| `public/` | Страницы, API (`public/api/`), скрипты и стили |
| `lib/` | Подключение к базе, общие функции, расчёт счетов |

## Страницы

| Страница | Адрес | Для чего |
|---|---|---|
| Рейсы | `index.php` | Журнал рейсов: куда, когда, на какой машине, сколько стоит |
| Карточка рейса | `trip.php?id=` | Грузы клиентов в рейсе и доля каждого клиента в стоимости |
| Счета клиентов | `invoices.php` | Счета за месяц: сумма, статус, когда отправлен клиенту и выгружен в 1С. Здесь же счета формируют |
| Счёт | `invoice.php?id=` | Из каких рейсов сложилась сумма счёта |
| Загрузка машин | `load_report.php` | Отчёт для логистов: насколько загружена машина по весу и какую часть веса занимает каждый клиент |
| Выгрузка счетов в 1С | `export_1c.php` | Файл для бухгалтерии: отправленные счета, которые ещё не выгружены |
| Пересчёт счетов | `billing.php` | Предпросмотр распределения по объёму и применение за выбранный месяц |

## Что добавлено

- `calc_trip_split()` распределяет стоимость рейса по суммарному объёму грузов каждого клиента.
- Суммы сначала считаются в копейках. Остаток распределяется методом наибольшего остатка, при равенстве по `client_id ASC`.
- API рейса возвращает номер, стоимость, клиентов, количество позиций груза, объёмы, доли и суммы.
- В карточке рейса отображаются старый расчёт по весу и новый по объёму для сравнения.
- Объёмы можно заполнить и исправить в карточке рейса. Пустое поле сохраняется как `NULL`.
- Предпросмотр счетов не записывает данные. Применение создаёт недостающие счета и пересчитывает существующие в транзакции.
- Повторное применение на тех же данных не меняет счета и ID строк, не создаёт дублей.
- Экран пересчёта доступен из меню и со страницы счетов. Перед применением запрашивается подтверждение.

## Проверка API

```bash
curl "http://localhost:8000/api/trip_split.php?trip_id=11"
curl "http://localhost:8000/api/billing_preview.php?period=2026-10"
curl -X POST -d "period=2026-10" "http://localhost:8000/api/billing_apply.php"
```

В PowerShell вместо `curl` используйте `curl.exe`. Последний запрос применяет пересчёт.
Денежные поля API возвращаются строками с двумя знаками после точки.
Некорректные параметры дают `400`, отсутствующий рейс - `404`, неподдерживаемый метод - `405`.
Если расчёт невозможен из-за объёмов, API возвращает `422`; применение не меняет счета.

## Проверки

```bash
php tests/billing_period.php
php tests/cargo_volumes.php
```

Либо в Docker Compose:

```bash
docker compose exec app php tests/billing_period.php
docker compose exec app php tests/cargo_volumes.php
```

Проверки используют SQLite в памяти и не изменяют рабочую базу. Проверяются предпросмотр,
распределение до копейки, создание и обновление счетов, повторное применение, изоляция месяцев,
откат при ошибке, валидация объёмов и принадлежность груза рейсу.

## Отличия от задания и оставшиеся действия

- По запросу пользователя вес исключён из нового API и таблицы по объёму. Это отличается от примера API
  и перечня колонок в задании. В старом расчёте и списке грузов вес сохранён.
- Если общий объём рейса равен нулю, расчёт останавливается. Автоматического перехода на вес нет.
- Пересчёт октября через экран и фиксация результата после применения остаются отдельным шагом.
- Записи экрана хранятся отдельно на Яндекс Диске. Доступ проверяющему пока не подтверждён.
- Старый обработчик `billing_run.php` сохранён для совместимости; новый экран использует preview/apply по объёму.

Ключевые запросы к ИИ-агенту приведены в [AI_SESSION.md](AI_SESSION.md).
